# Skyfire 1943 多语言与 Steam 发行宣发计划

更新日期：2026-10-15。用户要求支持 Mac、Windows、约 12 种语言，并把后期 Steam 上架和宣发纳入计划。当前 v0.16 是 Mac 本机单人样段，已有我方像素姿态、单人键盘改键与手柄输入路径，尚无完整多语言、Windows 实测、Steam 接入、商店页或公开发布。语言清单与地区版本见下文；宣发渠道、预算和日期待确认，阶段安排见[路线图](ROADMAP.md)。

## 已确认目标

- 发布平台覆盖 Mac 与 Windows；两边都需要可以直接运行的玩家应用。
- 保留单人，并支持[本地与互联网 2P](MULTIPLAYER.md)目标。
- 本地横版 / 俯视同屏，追尾分屏；互联网每人完整画面。
- 联网验收按 Mac ↔ Windows 互通规划，不仅测试两种系统各自能启动。
- Steam 是后期发布方向，没有因此确定发布日期、售价、首发机型或全部功能清单。
- 多语言以约 12 种为目标，纳入用户明确要求的日语、西班牙语、葡萄牙语、意大利语、法语、俄语。覆盖游戏内文本，并配套商店和宣传文案；不自动包含多语言配音。
- 宣发贯穿可展示 Demo、商店页、外部试玩、正式发售与发售后支持，不只安排在最后一天。

两平台适合使用同一套玩法与状态协议，分别导出本机安装内容。Steam 同一游戏可以配置不同操作系统的内容包；通常不需要把 Mac 和 Windows 当成两款游戏建立两张独立商店页。参见[Steam 平台与内容包说明](https://partner.steamgames.com/doc/store/application/platforms)。

## 现在需要预留的实现边界

以下是工程建议，尚未实现或确定具体依赖版本：

- 玩法模拟与窗口、输入设备、观察视图、平台服务分开；联机协议不要绑定 Mac 路径或设备名称。
- 玩家、弹组、敌人、掉落和关键事件使用稳定标识及模拟帧；不能假定不同 CPU / 系统的本地浮点模拟会永久一致。
- 按玩家分配操作意图，再适配键盘、手柄或未来 Steam Input；保留单键盘双区域能力。
- 构建脚本、导出资源、保存路径和版本标识可跨平台维护，保留开发者包与玩家包的功能隔离。
- 文本、字体、缩放和控制器提示必须在两平台验证。当前菜单优先使用 Heiti / PingFang 系统字体；正式版需选择可合法分发、覆盖目标语言的字体及回退方案，不能假设 Windows 安装了 Mac 字体。
- 房间 / 邀请与网络传输留出适配边界，方便 Steam 版接入平台服务；当前独立试玩不因缺少 Steam 客户端失去单人或本地多人入口。

## 多语言范围与制作顺序

用户将目标扩展为约 12 种，并明确要求包含日语、西班牙语、葡萄牙语、意大利语、法语、俄语。沿用简体中文、繁体中文、英语的基础建议，另建议德语、韩语、波兰语，形成以下 12 个本地化选项；简中与繁中分别计数。新增三种和西语／葡语的地区版本仍待确认，不把整张清单都写成用户已经逐项批准。

| 序号 | 语言与建议地区版本 | 计划依据 |
| --- | --- | --- |
| 1 | 简体中文 | 沿用基础清单 |
| 2 | 繁体中文 | 沿用基础清单 |
| 3 | 英语 | 沿用基础清单 |
| 4 | 日语 | 用户明确纳入 |
| 5 | 西班牙语（西班牙） | 用户明确纳入西语；地区为建议 |
| 6 | 葡萄牙语（巴西） | 用户明确纳入葡语；地区为建议 |
| 7 | 意大利语 | 用户明确纳入 |
| 8 | 法语 | 用户明确纳入 |
| 9 | 俄语 | 用户明确纳入 |
| 10 | 德语 | 补足名额的建议 |
| 11 | 韩语 | 补足名额的建议 |
| 12 | 波兰语 | 补足名额的建议 |

Steam 将西班牙西语与拉美西语、葡萄牙葡语与巴西葡语分别列为语言选项。这里先各建议一个地区版本，不用同一份翻译自动宣称两种地区版本都已支持；若之后同时制作两个版本，单独安排审校，并重新核对总数。[Steam 支持语言列表](https://partner.steamgames.com/doc/store/localization/languages)。

先以中文与英文小样验证技术和布局，再按约 12 种的目标分批翻译和验收；早期小样只有两种语言，不代表正式目标缩回两三种。文案频繁变更时先维护原文和术语，稳定后扩展翻译。

覆盖范围包括主菜单、设置、三视角 HUD、必要按键说明、任务与电台字幕、关间故事、武器和道具、危险警告、失败原因、单关结算／战役总评／排行榜、未来联网错误，以及商店介绍和宣传片字幕。玩家在正常关卡中学习，不另设独立教程。游戏文本、商店文案、配音分别验收；Steam 也区分商店本地化与游戏内语言，并按界面、字幕、完整音频标注支持情况。[Steam 本地化说明](https://partner.steamgames.com/doc/store/localization)。

制作流程建议：

1. 在 M1 的 UI 与玩法迭代中整理玩家可见文本，以稳定标识关联翻译，不把词句写进贴图或用多个短词硬拼句子。动态数量、按键和玩家名称使用参数，保存与网络状态不依赖翻译后的名字。
2. 在 M2 建立语言选择、偏好保存和缺失翻译回退；首次选择可参考系统／Steam 偏好，玩家手动选择优先。不支持的语言回退到明确的默认语言，不影响离线单人启动。
3. 为燃油／能量、三武器、保险、任务和 Boss 建立术语表，给译者提供语境和界面截图。繁体中文做用词校对，不只机械转换字形；机器翻译可作草稿，发布前需要目标语言审校与游戏内检查。
4. 在 M3／M4 随已稳定内容分批翻译，标记源文变更与待复核条目；M5 补齐合作、分屏、房间和错误文本；M6 做发布版逐语言验收。

三视角 HUD 的布局定稿须同时容纳加长文案、汉字／日文假名／韩文、西里尔字母、拉丁字母附加符号和不同数字格式，不靠无限缩小字体解决。早期可用加长测试文案与目标字形样本检查布局，不把测试文本当作已完成翻译。检查菜单、任务提示、Boss 名称、低燃油／低空警告和结算的裁切、换行、遮挡与阅读时间；未来追尾分屏使用更紧凑的视窗再测。本地同屏／分屏建议共用该客户端语言，互联网各端可独立选择，不改变判定、分数或队友状态。

完成条件：目标语言的玩家流程无遗漏、乱码或占位符；核心术语一致，字体随包合法分发；Mac／Windows 各做菜单到结束的实机检查。Steam 语言勾选与实际验收一致，不因商店描述已经翻译就声称游戏支持该语言。

## Steam 互联网合作建议

建议 Steam 版评估 Lobby 与好友邀请管理会话，Steam Networking 传输游戏数据，按适用情形使用 Valve 中继。官方说明提供这些连接与会话能力；仍需游戏自身完成同步、命中确认与掉线处理。[Steam Lobby](https://partner.steamgames.com/doc/features/multiplayer/matchmaking)、[Steam Networking](https://partner.steamgames.com/doc/features/multiplayer/networking)。

采用玩家主机或专用判定服务器，仍是待定架构选择。Steam 平台服务可以减少部分自行搭建的会话 / 中继工作，但不能直接承诺无需服务成本、无需 SDK 集成或所有网络必然连接成功；非 Steam 试玩如何提供公网联机也需确定。

尚未选择或安装 Godot 的 Steam 接入插件 / SDK 绑定。接入前要核对 Godot 4.7.2 与两平台原生扩展的兼容性、许可、Steam App ID 与实际客户端环境。

## Remote Play Together 的定位

可以在本地多人稳定后评估 Remote Play Together，供好友远程参与本地合作。它使用主机画面串流与远端输入，不能把启用功能选项当成原生联网完成。[Steam Remote Play 官方说明](https://partner.steamgames.com/doc/features/remoteplay)。

本项目本地追尾采用分屏，因此标准 Remote Play Together 路径仍沿用本地分屏布局。用户要求的互联网联机各自完整追尾视图，需要独立联网会话与各端渲染。两种能力应在商店说明与验收中区分。

## 发布准备与时间口径

2026-10-02 的平台核对记录：Steam Direct 每个新产品费用为 100 美元或等值地区金额。[官方费用说明](https://partner.steamgames.com/doc/gettingstarted/appfee)。首批产品通常还涉及付费后至少 30 天等待、公开“即将推出”页面至少两周和发布前审核；这只是平台门槛，不是项目开发工期或上架保证。[Steam Direct 流程](https://partner.steamgames.com/steamdirect/?l=english)。实际开通与支付时应再次核对，本轮不据此承诺日期或费用总额。

发布阶段由项目 Owner 完成必要的 Steamworks 身份、协议、收款和税务资料，另行决定售价与日期。本轮没有注册、付款、签署协议或提交商店页。

商店页公开、Demo 发布、游戏正式发售是三个不同节点；Steam 联网 SDK 接入又是独立工程任务。商店页和产品构建需要分别审核，排期应留出修改与复审余量，不把提交审核当天当成可发售日。[Steam 审核流程](https://partner.steamgames.com/doc/store/Review_Process)。

商店素材应基于真实游戏：截图、预告片、玩法和系统要求与已交付内容一致。保留原创资产与许可清单，不加入原作 ROM、美术或音乐。按最终产物和提交时的官方问卷如实填写内容说明及适用的生成式 AI 使用信息，不在本轮预先代填声明。[Steam 内容调查](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)。

成就、云存档、Steam Input 原生映射、Remote Play Together 与 Steam Deck 兼容性，是可以评估的附加功能，当前没有实现或列为首发承诺。尤其云存档依赖尚未实现的游戏存档规则。

## 宣发与试玩计划

以“三视角连续作战、像素活塞战机、三武器路线”为候选表达，先用陌生玩家试玩验证卖点能否被理解。合作仅在真实可用并验收后加入演示，不用本地双实例或概念稿冒充公网实机。游戏名与 Logo、中文／外文介绍保持一致，不暗示与参考作品有官方授权关系。

| 节点 | 计划产物与动作 | 开始条件与验收 |
| --- | --- | --- |
| M1 内部准备 | 一句话介绍、目标玩家假设、名称／术语与素材来源清单 | 卖点来自实际目标；尚未实现的内容明确标注，不对外承诺日期 |
| M2 可展示 Demo | 准备小范围陌生玩家试玩与反馈入口；实机图／视频、Logo／胶囊图草案、媒体资料包和多语言商店页 | 用户确认邀请后组织试玩，不靠开发者旁讲；宣传素材审定、Owner 确认账号与公开内容后才发布 Coming Soon 页 |
| M3／M4 持续外部试玩 | 按早期反馈修正 Demo，验证正式关卡与难度，更新开发进展；评估 Steam 新品节等活动 | 已有稳定可下载版本和处理反馈的能力；扩大邀请与报名另行确认，逐次核对资格和时间 |

| M6 上架与发售 | 商店／构建审核、平台配置、正式安装升级验证、多语言公告与首发支持安排 | 用户确认价格与日期，审核和实机验收完成后，由用户决定正式发布 |
| 发售后 | 收集缺陷与评价、优先修复阻断问题、补丁说明、更新宣传资料 | 有明确的反馈负责人和处理能力；不提前承诺 DLC、更新频率或销量 |

可展示版本就绪后，建议先公开 Coming Soon 页承接关注与愿望单，而不是等所有内容做完才准备页面；这与 Steam 的官方愿望单建议一致。[Steam 愿望单说明](https://partner.steamgames.com/doc/marketing/wishlist)。公开页面不等于承诺立刻发售，也不改变单人优先、合作后置的开发顺序。

Steam 新品节仅列为候选活动，不现在锁定某一期。当前官方要求包括游戏未发行、已有公开商店页、提供可玩 Demo，且同一游戏不能重复参加；报名时再次核对资格与具体时间，Demo 品质与修复能力不足时不为赶活动强行提交。[Steam 新品节说明](https://partner.steamgames.com/doc/marketing/upcoming_events/nextfest)。

渠道先少而可维护：Steam 公告作为产品信息入口，中文／海外视频或社区各选少量渠道复用实机素材；B 站、YouTube 等只是候选，不代表本轮创建账号或发帖。媒体资料包包含简介、已验证特点、平台／语言状态、Logo、实机图与授权可用的视频；未经确认不公开私人联系方式或未发布资产。

反馈既看关注也看体验：记录可获得的商店访问、愿望单变化、Demo 完成与退出原因、常见失败点、不同语言的反馈质量；没有基线前不编造转化目标或销量预测。新增游戏内统计需另行决定采集范围和告知方式，不默认上传玩家数据。

预算按翻译与审校、可分发字体／音乐、商店美术、预告片制作、测试设备和可选推广分别评估。委托、付费广告、创作者合作、活动报名、公开发布和自动定时发帖都不由本次计划授权。游戏内生成式 AI 使用与资产来源仍按实际制作记录填写平台问卷。

## 候选推进顺序与验收

主开发顺序继续按[路线图](ROADMAP.md)保持单人优先、合作后置；语言基础与素材归档从 M1 穿插，M2 起准备商店页和外部试玩，M3／M4 完成选定语言与两平台单人验证，M5 补合作，M6 做最终审核与发行。语言、商店和宣发不必排在联网之后，平台 SDK／公网验证按功能依赖安排。

约 12 种语言、上架与宣发是用户确认的计划范围；补足名额的三种建议语言、西语／葡语地区版本、渠道、预算、活动和发布日期仍待选择。首发是否分批、是否抢先体验必须由用户另行决定，不因为规划宣发就缩减既定平台与合作目标。

单人游戏、三种本地输入组合、独立追尾观察、网络命中与奖励唯一性，以及 Mac–Windows 互通均需记录版本和实测结果。只有通过目标平台和 Steam 客户端验证的功能才能在商店页勾选或宣传；最终还需通过平台审核，不能用源码测试或本机导出代替。
