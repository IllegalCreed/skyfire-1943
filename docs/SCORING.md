# Skyfire 1943 分数与排行榜

更新日期：2026-10-15。用户要求把分数与排行榜纳入核心体系，并明确每关结算后继续下一关、全通后展示排行榜。现有原型已经计分并有样段结果页，但没有正式关间流程、本地高分持久化或在线榜；以下计分扩展、榜单分组和上线顺序为讨论草案。

分数用于鼓励精进与重玩，基础燃油和必要成长仍由正常关卡流程提供，不要求玩家先会刷高分才能生存。设计与[关卡](CAMPAIGN.md)、[武器](WEAPONS.md)和[奖励与保险](PROGRESSION.md)一起验证。

## 当前计分

来源：[主程序](../src/main.gd)、[射击规则](../src/gameplay/chase_gun.gd)和[关卡导演](../src/gameplay/mission_director.gd)。下列为已实现、尚可调校的分值，单位均为分。

| 事件 | 当前分值 |
| --- | --- |
| 横版／俯视普通空中目标击破 | 200 |
| 追尾普通目标击破 | 按现有阶段／距离分档为 150、200 或 300 |
| 普通水面目标击破 | 对应基础击破分的两倍 |
| 拾取综合补给 | 100，同时恢复 18 点能量并设为二级火力 |
| 海鸥击破 | 2400 |
| 样段胜利 | 另加 1000，以及四舍五入后的剩余能量每点 10 分，仅结算一次 |

当前切换视角保留分数，整段重试清零。上述分数不是最终战役标准；练习场和正式关卡不能据此直接混排。当前设置存储不等于成绩存储。

## 初版计分结构

建议总分由基础击破、编队／任务表现、有限拾取奖励和关末评价构成，先不加入无限叠乘连击。

| 来源 | 鼓励的行为 | 边界 |
| --- | --- | --- |
| 基础击破 | 完成战斗 | 按敌种和目标价值给分，不按武器命中次数给分 |
| 编队全灭 | 在正常离场前完成整组击破 | 编队唯一标识，每组最多结算一次 |
| 可选目标或危险路线 | 击落奖励机、完成有预警的挑战 | 进入危险区域或停留本身不持续加分；事件完成后一次结算 |
| 关末表现 | 击破率、剩余能量、受击与救援记录 | 加分有上限，不把失误变成全部已得分归零 |
| 多余补给 | 满级后的拾取仍有反馈 | 转换值有限，不能刷新同一道具反复获利 |

不因激光持续命中次数多、散弹弹粒多、导弹爆炸波及多或僚机同时开火而重复奖励同一次死亡。范围攻击可正常取得多个实际被击破目标的分数，但不能按特效数量给分。

若以后采用速杀奖励，起点须是敌人首次可以有效交战的时刻，不能从追尾远处尚不可命中的入场开始倒计时。贴海穿越、Boss 部件与功能天气尚未实现，不提前在现版显示对应奖励。固定距离 Boss 不因持续摆动、等待或重复受击产生无限分数。

## 与燃油、保险和升级的关系

基础燃油补给保留。高分奖励以成绩为主，不作为基础燃油、第一件关键升级或通关必需武器的唯一来源；金色奖励机可以提供额外收益，逃走不能让流程必败。

合法获得的护盾和救援属于构筑选择，不建议使用一次就失去排行榜资格。可以设有上限的无伤／未救援关末加分，并记录使用情况，但要防止保命路线天然无法竞争。等级、武器和僚机收益须与关卡一起调校，不能只测满装备的最高伤害。

检查点恢复必须同时回滚分数、已领取奖励和编队事件，禁止“重试保分、重复吃道具”。候选规则是整段不接关的挑战进入标准榜；接关／检查点重试另存个人通关记录。暂停不取消资格，练习、开发快捷入口和调试注入的成绩不进入标准榜。中途存盘续玩能否保持资格，取决于以后能否防止反复读取刷分，暂不承诺。

## 本地榜优先

### 单关结算与全通总评

单关结果与战役总评使用同一份结算数据：每关展示本关分项、本关合计和战役累计分，再继续下一关；最后一关的分数先正常计入累计，总评不重算或再次加上关末奖金。若以后另设全通奖励，需单列规则并只发放一次，当前没有确定额外分值。

通关总评展示各关成绩、总分、通关情况和个人最佳，随后显示对应榜单并突出本次成绩。未进入标准榜的记录说明原因，仍可查看个人通关结果；不因检查点或调试成绩不合资格就隐藏整个结束流程。单关挑战与完整战役各自归榜，不把中途一关的累计分误报为完整战役通关。

连续确认、结果页重入、关卡加载重试和程序恢复不得重复发奖或提交同一成绩。在线排名尚未取得时明确显示离线／待获取，先给本地结果，不显示假的全球名次，也不让网络等待卡住重玩或返回。

### 离线纪录

第一步在单人 Demo 内做离线个人纪录与本机高分表，不依赖 Steam 登录或互联网：结束时展示总分、分项、进度／是否通关、个人最佳及本次是否破纪录；主菜单提供查看入口。失败也可以留下合法挑战成绩，不只有通关才记录。

榜单按照规则版本、挑战内容、难度和人数隔离。同一完整任务的三视角累加为一个总分，不切成三个互不相关的战役榜；单关挑战与整段战役独立。初版只开放实际存在的内容和难度，不做空白榜单。

记录包含总分、分项、关卡进度、用时、难度、模式、日期、规则版本、构筑及救援／继续记录。普通分数榜以总分降序为准，同分不额外推导速通优劣；存储用稳定顺序展示。榜单保留条数与是否允许本地署名待 UI 小样确定。

仅显示辅助、分辨率和控制器类型不改变判定，不因此分榜。未来改变伤害、速度或无敌能力的模式必须独立；不同武器先在同榜检验平衡，不为每种配装拆大量空榜。

## Steam 在线榜

计分规则稳定后再接入在线服务，候选为 Steam 全球榜与好友榜。Steam 提供持久化排行榜、个人最佳上传与可附加的对局数据；这并不自动验证成绩真实性。[Steamworks 排行榜文档](https://partner.steamgames.com/doc/features/leaderboards)。

本地榜的数据结构先保留规则版本与对局标识，但不现在部署服务器、安装 SDK 或建立账号。后续需要落实：

- 在线榜只接收兼容版本的正式挑战；规则或平衡发生实质变化时保留旧榜，并启用新规则榜。
- 校验不可能的分值、关卡顺序、重复结算及调试标记；客户端自报成绩与日志只能降低误报，不能宣称可靠防作弊。
- 决定是否需要可信服务端验证或回放复核。Steam 的可信写入配置需要服务端写入流程，不把密钥放入游戏包，也不以本地文件哈希冒充反作弊。
- 离线仍可玩且保存个人成绩；符合验证政策的成绩才排队补传。上传失败不能丢本地纪录，重复重试不能生成重复成绩。
- Mac 与 Windows 使用相同规则时可同榜。合作阶段新增双人团队榜，不混入单人榜；个人贡献可以展示，但不鼓励抢最后一击。

接入在线榜不要求提前完成互联网合作，两者是独立能力。具体开发顺序见[路线图](ROADMAP.md)：M1 定义计分事件，M2 验证本地榜，M3／M4 调校正式关卡，在线榜在规则稳定和平台依赖就绪后接入，最迟在选定发行范围验收时检查。

## 验收

- 三种武器与僚机同帧命中、Boss 击破、胜利重入均不重复计分或掉落。
- 各关分项与战役累计一致，最后一关奖金不在总评重复发放；结果页连续确认不跳关，通关后可查看本地榜并重玩／返回。
- 失败、重试、检查点、暂停、转场及不同刷新率下的分数一致；可选风险事件不能原地无限刷。
- 本地纪录重启后保留，损坏或旧版本文件有安全回退；测试使用独立文件，不污染玩家高分。
- 玩家能看懂分项和进榜资格；不同内容、难度、人数、规则版本不混排。
- 正式在线验收涵盖离线、超时、重复上传、旧版本和异常成绩；未完成前不显示假的全球名次。
