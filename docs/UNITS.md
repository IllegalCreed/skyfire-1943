# Skyfire 1943 单位造型与奖励敌机

更新日期：2026-10-14。当前 v0.16 接入我方像素姿态，保留 v0.11 的普通敌种和 v0.15 的海鸥 Boss 验证版；数值为原型调校，主观外观与难度仍待试玩。完整部件 Boss 和岸防静态炮台仍为[战役草案](CAMPAIGN.md)。

## 造型目的与背景

用户反馈原有敌我单位过于抽象，要求更帅并符合 1943 背景，同时强调敌船需要单独设计。沿用原创几何绘制和现有配色，强化活塞式螺旋桨、带框座舱、发动机整流罩、金属面板、尾翼与船舶上层建筑；不加入喷气尾焰、现代导弹、箱式集装箱或未来战机轮廓。

我方为架空双发、双尾撑战斗机；轻型截击机采用短鼻星形发动机，袭扰机采用长鼻宽翼，双发攻击机采用宽翼、双发动机、双垂尾与玻璃机鼻。三视角和僚机使用同一套结构身份，侧视敌机只水平镜像。追尾我机使用独立后视绘制，看到双尾撑、尾翼、座舱后窗、机身尾部和发动机后段，不展示发动机正面的进气环、桨毂或完整螺旋桨盘；迎面接近的敌机使用正视。青绿表示我方，暖红识别条表示普通敌方，金色表示奖励敌机；折线识别纹样为原创。

结构观察参考：[美国空军博物馆 P-38 资料](https://www.nationalmuseum.af.mil/Visit/Museum-Exhibits/Fact-Sheets/Display/Article/196280/AFmuseum/lockheed-p-38l-lightning/)、[B-25 资料](https://www.nationalmuseum.af.mil/Visit/Museum-Exhibits/Fact-Sheets/Display/Article/196310/north-american-b-25b-mitchell/)、[海军历史机构 Fletcher 资料](https://www.history.navy.mil/content/history/nhhc/browse-by-topic/ships/modern-ships/uss-fletcher.html)。仅用于理解二战机械结构，没有导入照片、原作图像或历史阵营徽记，也不把架空机型标为真实型号。

## 敌船与静态防御状态

护航炮舰使用细长船体、前后炮塔、分层舰桥、双烟囱和甲板鱼雷管；武装运输船使用货舱盖、吊货桅杆、后部舰桥及烟囱。俯视显示甲板布局，追尾显示船体和上层建筑，两种船可从轮廓区分。背景船队共用运输船造型，以低对比绘制，仍没有可攻击 / 保护目标逻辑。

| 已实现单位 | 现有战斗参数 |
| --- | --- |
| 护航炮舰 | 耐久 7 次普通机炮命中；追尾 1 枚鱼雷；俯视开火间隔 2.5 秒，追尾 3.4 秒 |
| 武装运输船 | 耐久同炮舰；俯视与追尾开火间隔均为 5.2 秒 |
| 两种敌船共通 | 单发瞄准炮弹；俯视弹速 155 逻辑像素 / 秒，追尾弹速 30 内部单位 / 秒；俯视随场景以 42 逻辑像素 / 秒下移 |

参数集中到[敌种配置](../src/gameplay/enemy_roster.gd)，数值沿用旧实现。首次出现后的初始开火等待和稳定开火间隔分开：自然波次俯视首次等待 1.8 秒，追尾 3.5 秒。外观中的炮塔、鱼雷管和桅杆不代表新增独立攻击或可破坏部件；目前伤害与瞄准仍是整艘船的规则。

俯视当前可攻击的水面单位是两种敌船。机场、码头和岸上建筑只是背景，尚无可交战的岸防静态炮台。图鉴将岸防炮台与六关 Boss 明确放入“设计草案”，不以新图鉴或船体细节暗示其已实现。

## 金色奖励敌机

目的：给玩家一个可选的快速高价值目标，奖励及时发现、追踪和射击。用户明确要求快、颜色特殊、不易命中、击落掉道具。当前内部类型为 `courier`，三种视角均已实现。

| 项目 | 已实现参数或规则 |
| --- | --- |
| 出场 | 每 5 个已生成波次的第一架，用奖励敌机替代；不额外增加波次或同屏容量 |
| 外观 | 金色机身、浅色识别条、小型单发螺旋桨机 |
| 横版移动 | 240 逻辑像素 / 秒，自主摆动幅度 80 逻辑像素，角频率 3.8 弧度 / 秒 |
| 俯视移动 | 175 逻辑像素 / 秒，同样的自主摆动幅度和频率 |
| 追尾路线 | 接近阶段时长 4.3 秒，横向路线摆动参数 76 逻辑像素；阶段结束继续侧飞，完全越界才清除 |
| 耐久 | 二维 1 次主炮命中，追尾 1 次有效汇聚命中；命中框沿用同阶段普通敌机规则 |
| 攻击 | 不主动开火，优先逃离；机体接触仍按原规则伤害我机 |
| 掉落 | 击落必掉 1 件金色 B 综合补给，逃走不掉落；若同时恰逢第四次击落，只掉 1 件 |
| 拾取结果 | 恢复 18 点能量，火力设为二级，加 100 分；结果跨视角共享 |
| 追尾掉落寿命 | 14 秒；空域补给每秒下移 35 逻辑像素，共用观察滚屏和原拾取判定 |

难点是较快的飞行、短接近时间与横向摆动，不通过缩小既有命中框改变规则。追尾仍需有效距离和第 16～19 帧汇聚窗口；不自动锁定。二维 X 的原有清弹伤敌仍可击落奖励敌机。未击落不影响普通每四次击落补给，三视角切换继续使用既有清理接缝。

奖励复用[当前综合补给](PROGRESSION.md)，不等于 P/E/S/C/R 独立道具或三级共享主炮已经实现。开发者菜单新增“追尾 · 奖励敌机”，F1 返回场景菜单，重开可再次重现。

### 我方战机姿态设计稿（独立评审）

2026-10-13 用户要求删除此前不符合设计图的临时模型并按定稿三视图重建。旧 `wing-test` 文件已删除；当前新模型只保留在独立评审目录，不进入游戏场景。它按已认可的双发动机梭形舱、连续凸出的主翼、中央梭形机身、后半段上方连接杆、直尾梁和两片垂直尾翼建立。追尾俯冲必须主显示机腹、尾梁下侧和发动机舱下侧；拉升 / 俯冲只改变俯仰，不能滚转、偏航或替换机尾。俯视只保留中立、左倾、右倾三张，侧视只保留中立、左倾、右倾三张；侧视机头朝屏幕右侧，上下移动对应滚转，前后移动不改变姿态。

独立设计稿通过 `outputs/unit-designs/catalog.json` 维护并由[图鉴生成脚本](../scripts/build-unit-handbook.rb)内嵌到 `outputs/skyfire-unit-handbook.html` 的“我方战机设计稿”入口。平面比例参考保存在 `outputs/unit-designs/blender/skyfire-flat-reference-top.png`。2026-10-14 复查确认 v2 及旧 `skyfire-flat-*-measurements` / `skyfire-flat-*-stations` 标注存在轮廓和站位错误：包括将座舱盖尚未结束的位置标成零宽，以及平尾尺寸混入垂尾范围。此前 577 px 发动机、225×92 px 座舱盖等记录撤回为未通过核验的旧值，不再指导模型；旧稿保留为问题对照。

当前独立候选为 `outputs/unit-designs/blender/skyfire-airframe-v3.blend`。共享参考数据在 `work/blender/airframe_v3_reference.py`，生成脚本为 `work/blender/skyfire_airframe_v3.py`。所有部件共用原始 1254×1254 px 坐标，不再分别缩放裁剪图。v3 建模采用的近似轮廓为：中央机身 y=118～890 px；座舱组件 y=274～488 px、最大宽约 68 px（前段含金属过渡，玻璃自约 y=307 px 开始）；桨帽 y=190～240 px，桨叶轴在 y=244 px，发动机舱 y=258～780 px，两发动机轴相距约 404 px。平尾中心弦长约 103 px（y=955～1058 px），不包含垂尾延伸。上述值是本版原图轮廓拟合参数，不是物理尺寸或已获用户确认的精确测量；后尖与翼根的遮挡区域尤其需要推定。

主翼和平尾使用连续封闭翼型，尾撑从发动机后半段上方接入并保持平行；座舱框、青蓝双折线与细节沿各自曲面铺设。桨帽、桨叶、发动机及连接杆保持独立结构，螺旋桨有均匀旋转驱动。当前只有程序材质和几何表面细节，未完成最终手绘贴图或像素化。`skyfire-airframe-v3-reference-overlay.png` 将实际网格投影叠回原图，另有 `top`、`rear`、`perspective`、`front-quarter`、`wing-detail`、`cockpit-detail` 六张独立渲染。检查结果与可见轮廓抽样范围见[开发进度](DEVELOPMENT.md)。厚度、垂尾高度和机腹形状仍是待确认的三维方案，不能从单张俯视图声称已精确恢复。

v3 结构修正阶段未更新 HTML。随后用户认可该轮效果并要求开始后续工作，因此将 v3 作为本轮姿态基准；这不等于已认可所有三维推定、最终贴图或新姿态。定稿图的暖象牙 / 冷灰机体、青蓝装饰纹路和活塞螺旋桨位置继续约束后续造型；禁止把后视画成机头正视、喷气尾焰或后置进气口。

| 视角 | 独立姿态 | 本轮预览规则 |
| --- | --- | --- |
| 俯视 | 中立、左倾、右倾 | 机头向上；滚转 ±26°，无俯仰和偏航；相机约 67° 高位俯看，使滚转可读 |
| 横版 | 中立、左倾、右倾 | 机头向右；滚转 ±26°，无俯仰和偏航；暂按上移左倾 / 下移右倾展示，未改控制逻辑 |
| 追尾 | 中立、左倾、右倾、抬机头、压机头 | 相机在机尾；滚转 ±25°；抬头 +23°、压头 −25°，两者滚转均为 0°；压头主显示机腹 |

左右以飞行员朝向为准。模型图为透明背景 1200×1200 px（俯视）或 1200×900 px（其余）；像素候选为原生 320×320 px 或 320×240 px，采用分阶配色与主体轮廓线，并非最终手绘像素贴图。相机在每个视角内固定，原始 `.blend` 文件及原机体局部网格坐标哈希保持不变，姿态 / 机腹朝向 / 画框检查记录在 `pose-validation.json`。这些是独立评审素材，尚未接入游戏，也未覆盖 `src/rendering/aircraft_art.gd`。

随后用户指出六帧、每帧 83 ms 的清晰桨叶循环显得过慢，要求动漫式高速白圈，并明确至少两帧闪烁。当前十一种像素姿态均改为八帧、每帧 40 ms 的高速桨盘候选：淡白底盘持续保留，白色外缘与短弧残影按亮 / 暗两态交替，弧位置随帧变化。外缘透明度 0.24 / 0.43、亮弧透明度 0.60 / 0.90、底盘透明度 0.065 均为本轮待审视觉参数；25 fps 是预览帧率，不是物理发动机转速。

效果由 `work/blender/propeller_speed_fx.py` 在原桨轴添加仅渲染用的薄桨盘 / 弧面，像素输出隐藏实体桨叶，不删除或修改原模型。追尾按圆盘、俯视按椭圆、横版按薄亮影投影，并参与正常深度遮挡；不使用覆盖机体的屏幕贴圈，不加入喷气尾焰。模型姿态图仍保留静态实体桨叶用于结构检查。页面可暂停动画，减少动态偏好默认暂停；切换姿态沿用同一相位时钟及暂停状态。连续姿态中间帧、可操控预览和运行时接入尚未实现。

渲染和数据导出见[图鉴绘制](../src/rendering/unit_catalog.gd)，页面模板与装配见[HTML 模板](../scripts/unit-handbook.html)、[生成脚本](../scripts/build-unit-handbook.rb)。从仓库根执行 `bash scripts/build-unit-handbook.sh` 重生成；Mac 构建也会生成图鉴。普通敌种与舰船数据来自同一运行配置，我机共通说明和草案需随对应机制文档维护。

## v0.16 实际游戏姿态动画

2026-10-14 用户认可高速白桨盘效果，要求连续中间帧、合适占屏尺寸、像素化并实际试玩。因此此前“仅设计稿、未接入”的描述是前一阶段记录；当前我机、僚机、首页及转场均改用 v3 同一模型烘焙的原创像素帧。敌机和舰船未重做。运行时仍为 Node2D，没有加载 Blender 或引入 Camera3D。

| 视角 | 已实现视觉档位与控制 | 原生单帧画布 / px |
| --- | --- | --- |
| 横版 | 9 档滚转，−26°～+26°；上移左倾、下移右倾；前后移动不改姿态，无俯仰 | 80×60 |
| 俯视 | 9 档滚转，−26°～+26°；左右移动倾斜，机头保持向上；上下不改姿态，无俯仰 | 64×64 |
| 追尾 | 9×9 档组合；滚转 −25°～+25°，俯仰 −25°～+23°；压头显示机腹 | 112×84 |

以上为美术参数，不是物理飞行角度。共 99 个姿态，每姿态 8 个白桨盘相位，总计 792 帧；25 fps 曝光相位时钟独立于姿态选择。姿态按输入以每秒 6.25 归一化单位趋近目标，中立到满倾约 0.16 秒，反向先经过中立；追尾俯仰目标读取现有升降速率，达到高度上限回平。没有图像透明叠化，不产生两架飞机的重影。暂停冻结时钟，重开归零，普通姿态切换不重播桨盘。

每视角相机、光照、固定画框和中心不随姿态重裁；按真正三维组合旋转，滚转围绕机体纵轴，不额外偏航。六档材质色阶、实际小尺寸渲染、一像素外缘、最近邻采样保留像素颗粒。原生画布含透明余量，不能当作碰撞框；主机按逻辑像素展示，默认内部画面为 2 倍，僚机沿用缩小比例。源模型和原网格哈希检查保持不变，追尾炮口 / 汇聚、碰撞、能量、海面、转场冻结与敌方参数都不随美术调整。

实现见[姿态控制](../src/rendering/player_pose.gd)、[图集绘制](../src/rendering/player_sprite.gd)、[回归检查](../tests/player_pose_checks.gd)和[资源说明](../assets/README.md)。验收需要实际引擎输入动画、转场和导出应用；自动检查不代替用户对大小、细节与手感的认可。

## 验收

- 实际引擎核对三视角飞机、两种舰船、远处 / 近处和金色识别，并提供 Mac 两版试玩。
- 普通飞行、汇聚窗口、持续侧飞、密度、海空滚屏和隐藏舰船攻击回归仍通过。
- 三视角真实击落均掉奖励，实际拾取恢复能量与火力，不重复发奖，逃走不发奖。
- 图鉴图片使用实际绘制，数据与配置一致；单位选择、视角、对比和草案状态可浏览。
- 图鉴另有独立设计稿入口；每张姿态图单独展示，清楚区分 3D 结构校验、像素候选和运行时单位图，不把未审核稿写成已实现资源。
- 外观吸引力和奖励目标的主观难度仍需用户试玩，自动 PASS 不代表已获认可。
