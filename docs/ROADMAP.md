# Skyfire 1943 开发路线图

更新日期：2026-10-15。当前实现基线：v0.16 我方像素姿态动画，承接 v0.15 单人破晓突袭样段。

先用一小段关卡把环境机制、武器成长、奖励保险和计分连起来，再扩大敌人美术与战役，最后完成合作与正式发行。多语言基础提前进入 UI 工作，商店页与宣发从可展示 Demo 阶段穿插推进，不全部压到发售前。场景表现是玩法可读性的一部分，不能只改敌机、留下难以理解的危险色块。

单人优先、本地与互联网合作、Mac 与 Windows、后期 Steam 是已确认方向。用户进一步要求保留燃油补给、散弹／激光／导弹三路线、沙罗曼蛇式僚机、分数与排行榜，以及多语言和发行宣发计划。关卡、环境、成长与计分提前共同设计；下面的细分方案仍是规划建议，列入路线图不等于获准立即开发、发布或购买服务。具体玩法以专题文档为准，实际完成与验证证据记在[开发进度](DEVELOPMENT.md)。

玩家在正常关卡中学习，不设置独立新手教程、强制教学弹窗或完成指定操作才放行的教学关。沿用已有岛链突袭故事，以简短任务交代和关后结果串联关卡；每关结算后继续下一关，最终通关展示战役总评与排行榜。音乐音效、战斗反馈及下文的制作验收工作已获用户认可为计划方向，具体参数与产物仍逐项确认。

按用户建议，玩家 HUD 不显示波次编号或剩余波数，内部编排信息仅供开发调试；敌人通过职责、队形、路线、时机和组合保持新鲜度，不靠单纯增量。当前 HUD 仍有 `WAVE`，此项尚待实现；必要的攻击与环境危险预警继续保留。

## 阶段总览

M 表示开发里程碑，不是版本号，也不是按月排期。一个阶段可以包含多个可试玩的小版本；达到验收条件后再进入下一阶段。

| 阶段 | 交付结果 | 进入下一阶段的条件 | 当前状态 |
| --- | --- | --- | --- |
| M1 关卡与核心系统样板 | 环境可读的短关段，分批验证武器、奖励、保险和计分 | 先理解风险与选择，再通过实际试玩确认各机制收益 | 设计讨论中，未开始实现 |
| M2 单人品质 Demo | 选定玩法连成闭环，统一音画，加入本地高分纪录 | 三视角成长有效，从开始到结算与重试可反复游玩 | 待 M1 |
| M3 正式首关与规则收敛 | 完整第一关、稳定成长计分、关后结算与跨关流程验证 | 首关通过试玩，继承和结算不重复，后续内容清单明确 | 待 M2 |
| M4 完整单人内容 | 故事串联的战役、逐关结算、Boss、音画及全通总评／本地榜 | 全流程可通关、可恢复，素材与性能达到约定目标 | 待 M3 |
| M5 双人合作 | 本地 2P，再加入原生互联网 2P | 真实控制器与异地跨系统合作通过，单人不退化 | 待单人稳定及平台验证 |
| M6 上架与发行 | 经验证的多语言 Mac／Windows 包、Steam 审核与发售素材 | 首发范围、语言、平台、许可和审核验收完成，用户确认价格／日期 | 待首发范围完成 |

Windows 是贯穿后续阶段的平台工作：M2 稳定后启动，在 M4 收尾前完成已选目标机器的单人验证，不等多人做完才尝试导出。进入 M5 前确认公网技术路线；若依赖 Steam 服务，其接入验证也必须提前，不能全留到 M6。

语言目标按用户要求扩展为约 12 种：沿用简体中文、繁体中文、英语，纳入用户点名的日语、西班牙语、葡萄牙语、意大利语、法语、俄语，另建议德语、韩语、波兰语。简中与繁中分别计数；西语暂建议西班牙版本，葡语暂建议巴西版本，新增三种及地区版本待确认。详细清单统一维护在发行专题。M2 的中英文小样用于先验证技术，不缩减正式目标；后续按清单分批翻译并逐语言验收，文本本地化不自动包含配音。试玩邀请、媒体联系、账号、付款、活动报名和公开发布需另行授权；本轮只规划，不创建外部任务或自动发帖。

## M1 关卡与核心系统样板

先确认一段关卡的核心体验、画面层次、危险预告、安全路线、补给和得分机会。候选采用横版峡谷／雷雨场景，替换难以解释的红色危险区域；不是同时承诺岩壁、雷电、炮台、云中隐身等全部机制。每轮只实现一个可验收问题。

建议按以下顺序拆成小交付，每次都可独立试玩；不用等所有系统齐备才交付下一份应用。

1. 场景小样：先用现有武器和补给验证短片段，包含远山与雨幕、中景断崖／设施、清楚的交战层、近景视差和必要 HUD。先验证岩壁或雷暴边界，普通背景与真正障碍明确区分；闪电有蓄能和危险位置预告，不能随机命中玩家。普通雨不自动造成伤害或改变操控。
2. 武器小样：按[三路线方案](WEAPONS.md)分别测试散弹覆盖、激光持续集中输出、导弹齐射爆发；用同一批敌人对比，再单独验证追尾的汇聚与范围判定。没有完成的路线不冒充正式装备。
3. 成长与保险小样：保留基础燃油，选定升级／换装及一种保命候选；验证正常失误后的恢复，不把高难奖励作为基本补给唯一来源。僚机先测试跟随和真实开火，再评估三视角收益。
4. 计分小样：定义唯一的击破、编队、可选挑战和结算事件，检查三武器／僚机不会重复得分；本地榜的资格和记录格式在此确定。

轻型截击机仍作为第一种敌机美术样板，但按片段需要安排，不以重做全部敌人为上述玩法的前置。保持先轮廓结构、再关键姿态、再实际尺寸、最后连续帧的审定顺序；迎面敌机不能复用我机后视，造型更新不自动改命中框或血量。

验收看玩家能否说明危险来自哪里、为何受伤、换武器有什么收益，以及失误后怎样恢复。原空间规则与输入回归必须继续通过。交付具体小样的 Mac 试玩包和操作说明，不用设计图或自动测试代替体验认可；不同时扩展完整战役和多人。

新敌种、补给和环境先在宽松、可观察的航段出现，再与既有威胁组合。通过真实命中、拾取前后变化和危险预告让玩家理解规则，不暂停战斗讲解；必要按键说明仍可在设置查看。默认关闭机枪准心和鱼雷投弹点，不以教学为由强制打开或放宽追尾命中。

关段小样同时验证[波次差异与组合](CAMPAIGN.md)：用少量已有敌种编排单一威胁、变体与互补组合，记录各段期待的玩家选择及低压间隙。参考经典作品时区分具体平台与关段，先提炼路线和时序，再设计原创组合；不以扩充敌种数量替代节奏设计，也不先建立完全随机刷敌系统。

## M2 单人品质 Demo

把 M1 中通过试玩的规则接成小型完整流程，再按实际关段需要分批完善敌机、金色奖励机、敌船和海鸥。每批完成设计、接入和试玩后再制作下一批；图鉴继续区分设计稿与实际游戏素材。

同时打磨现有样段的敌弹与开火预告、命中和爆炸、奖励掉落与拾取、HUD、转场及声音层次。云、海、岛屿与背景建筑服务于战斗辨识，不要求所有背景都建精模。配乐先确定风格及合法来源，再制作样板，不提前铺满战役。

音乐音效和战斗反馈形成独立交付清单：先完成一个关段的道中／Boss 音乐样板与结算短音，再扩展各关。散弹、激光、导弹须有可辨的开火与命中声；另列击破、受击、补给、升级、保险触发、低燃油／低空、敌人攻击预告和风雨海浪。只为已实现事件播放反馈，实际命中与击破由战斗结算触发，不用特效重叠冒充命中。三视角共享事件语义，按观察关系调整表现；炮声与爆炸不能盖住关键警告，音乐循环、暂停、转场、胜败重试和音量设置需一并验收。

交付一份可反复游玩的单人品质 Demo：燃油、三武器候选与僚机在三视角验证，所选保险有明确代价，结算提供分项和本地高分纪录。现有样段仍是追尾 → 俯视 → 追尾；横版可以作为独立编排短关段，不为展示视角强行改写任务流程。

完成条件是玩家能够理解目标、攻击预告、命中和失败原因，关键敌弹不被特效遮住，敌我与奖励目标容易区分。开始、暂停、设置、胜败、重试和返回都应可实际操作；显示回切与实体手柄验证有明确结果，未验证的设备不得写成兼容通过。

正常 HUD 不显示波数；即使看不到编排编号，玩家仍能区分连续交战的应对方式。验证空中／水面组合、奖励追逐与环境叠加时有可行路线，清理较慢也不突破压力上限；只换颜色或加耐久不能作为波次多样性通过的证据。

小范围陌生玩家试玩提前到本阶段准备，经用户同意后组织；不靠开发者旁讲，观察首次交战、拾取、失败与重试是否可理解。保留问题和改版对照，不默认上传行为数据。当前 Demo 末尾明确显示本段完成，不伪装成完整战役通关或提供尚不可玩的下一关。

本阶段只整合选定的成长与环境机制，不把全部 P/E/S/C/R、部件 Boss 或随机天气一并加入。在线榜不阻塞离线单人验证。

## M3 正式首关与规则收敛

基于 M1／M2 的试玩结果稳定规则，未验证的选择不能直接写成正式配置：

- 成长组合：确认三路线等级、僚机数量、补给分布与保险代价；尚未选定的道具继续留在[成长](PROGRESSION.md)和[武器](WEAPONS.md)草案，不一次全上。
- 三视角收益：同一装备的作用、僚机定位、特殊攻击操作与消耗，避免换视角后升级失去意义。
- 失败与继续：整关重试、检查点、退出后续玩如何取舍，以及恢复时保留哪些状态。未采用检查点前不提前建立整套存档系统。
- 计分公平：确认[榜单](SCORING.md)的挑战资格、规则版本和反复刷分边界，比较三路线及保命构筑，避免某一方案成为唯一冲榜选择。
- 难度与重玩：先调好标准难度，再决定其他档位对编队、弹速和补给的调整；明确选关、练习与高分挑战的入口和资格，不默认新增永久属性养成。
- 战役串联：沿用[故事草案](CAMPAIGN.md)，确认每关目标、关后结果及下一关理由；单关结算显示分项与累计分，确认继续才进入下一关。跨关继承和重试回滚共同验证，可先用内部短测试关验证衔接，不把测试关作为正式内容宣传。
- 正式内容规模：关卡数、每关任务与核心体验、Boss 数量和首发必需系统。现有六关、约 27 分钟仍是[战役草案](CAMPAIGN.md)，不是必须全部兑现的排期。

将选定规则接入正式第一关，通过编队、补给、危险预告和 Boss 节奏让玩家在作战中学习，不只是延长现有刷敌时间，也不增设独立教程。横版另用编排战斗验证这些共享规则，不必硬塞进首关。

完成条件是所选成长在三视角都有效、普通失误仍有恢复机会、错过金色奖励机不导致流程必败，重试不复制补给或分数。交付完整首关试玩和经确认的后续内容清单；新数值均经单人试玩调校。

## M4 完整单人内容

按 M3 确认的范围逐关制作。每关先明确任务与变化，再落地编排、场景、敌种组合、补给、Boss、音频和结算；从头到尾试玩通过后才视为完成，不用关卡名称或时间表代替可玩内容。

岸防炮台、可破坏部件、天气与贴海战术仅在获准的关卡确有需要时逐项验证。新系统先做小样，对比是否改善体验，再决定复用；不因某关草案写过就全部实现。

阶段结束需完整单人通关、难度／资源／得分曲线、所选恢复 / 保存规则、最终音画、目标机器性能及长时间运行检查。关卡时长和性能预算在范围与测试机明确后设定，不预先虚构达标数字。计分稳定且平台条件就绪后可接入 Steam 好友／全球榜，不要求等待互联网合作完成。

完整流程为任务交代 → 关卡战斗 → 单关结算 → 下一关，末关结算后接简短收尾、战役总评和排行榜／个人最佳，再选择重玩或返回首页。单关与累计分清楚区分，末关奖金不能在总评再次计算；结算期间冻结战斗与能量消耗，连续确认不重复加分或跳关。没有网络时仍可查看本地纪录，在线榜失败不阻塞结束流程；具体展示与资格见[计分专题](SCORING.md)。

如果制作成本超过可承受范围，先重新确认尚未承诺的关卡与可选机制，不降低已认可的结构准确性，也不默默删去已确认的平台或合作目标。

## M5 本地与互联网合作

单人流程和体验稳定后启动，按[多人专题](MULTIPLAYER.md)分两步交付。

先做本地 2P：两玩家身份和独立输入，键盘＋手柄、两个手柄、同键盘双区域；横版与俯视同屏，追尾分屏。分屏布局、补给归属、复活、暂停与加入规则先确认。双人波次、目标分配、耐久和资源单独调校，保留单人基线，不把全部数值翻倍。合作团队分与单人榜隔离，伤害贡献与唯一击破结算不能鼓励抢最后一击。

再做互联网 2P：各端完整画面，共享同一场战斗。先选择会话入口、判定方、传输与中继方案及费用边界，再实现邀请或加入、同步、异常退出和重连政策。Steam 服务若被选用，需先取得必要账号与兼容验证；不得未经授权购买或部署服务。

验收包含真实设备、独立追尾观察、每位玩家的汇聚判定、奖励和结算唯一性，以及 Mac–Mac、Windows–Windows、Mac–Windows 的真实异地联机。局域网双实例和 Remote Play Together 都不能替代原生互联网联机验收。延迟与丢包按专题测试矩阵评估，不先承诺可玩上限。

## M6 上架与发行

在完成约定首发范围后冻结功能，集中处理缺陷、性能、可访问设置和兼容性。默认路线覆盖单人、本地与互联网合作；若要分批发布或抢先体验，由用户另行决定，不能为赶进度自行改成单人首发。

交付可直接运行的 Mac 与 Windows 玩家包，核对正式分发、安装升级、字体、控制器、存储位置和所选系统版本。首发语言覆盖菜单、三视角 HUD、任务、警告、结算与合作流程，不仅翻译首页。保留开发者入口隔离，整理原创资产、字体、音频与工具依赖的许可和来源。

Steam 商店截图、视频、功能说明与系统要求必须来自已验证成品。账号、协议、付款、税务、售价、发布日期和最终发布由用户决定；平台要求在接入时重新核对，详见[发布计划](RELEASE.md)。成就、云存档、Steam Deck 等不自动成为本轮首发承诺。

商店页公开、Demo 发布和正式发售分别验收；正式发售前留出商店／构建审核与返修时间，核对安装更新、回退预案、公告、支持入口和问题处理负责人。宣传片与商店介绍按选定语言准备，不用概念稿代替实际游戏截图。愿望单目标、推广预算、活动档期与售价在有依据后由用户确认，不编造保证销量的排期。

若采用 Steam 在线榜，需验证正式版本隔离、上传失败／补传、异常分数处理及 Mac／Windows 一致性；不能把支持排行榜等同防作弊完成。其账号与验证服务方案另行确认，不默认购买服务器。

## 贯穿各阶段的制作与验收

这些工作服务于既定玩法，不另设新的大型系统。阶段交付需同时给出对应证据，不能只完成菜单入口或文案。

| 工作 | 阶段与交付 | 验收重点 |
| --- | --- | --- |
| 三视角 HUD | M1 样稿，M2 实机；核心状态位置稳定，特殊仪表按视角安排；玩家不显示波数 | 不遮交战区，实际大小和长文案可读；波次调试不泄露到玩家画面，危险预警保留；未实现装备不显示伪状态，默认辅助开关保持原规则 |
| 音乐音效与反馈 | M2 一个完整关段样板，M3／M4 扩展，M6 最终混音 | 攻击、命中、击破和警告可区分；音乐／音效独立音量在真实接入后提供，无削波或明显循环断口 |
| 保存与升级兼容 | M2 本地成绩，M3 选定战役保存规则后实现，后续版本回归 | 设置、成绩、战役进度分开；写入中断、文件损坏和旧版本有恢复方案，不清空无关数据或复制奖励 |
| 可读性与舒适 | M1 预留，M2 实机验证，M5 复测分屏 | 道具兼用轮廓／图标，不只靠颜色；检查字幕、特效遮挡、晃动、雷电／激光／桨盘明暗变化；减弱表现不改变判定或删掉危险预告 |
| 素材与关卡制作 | 批量制作前确定像素尺寸、调色、姿态、锚点及配置约定 | 保留独立设计稿与实际尺寸验收，源模型／脚本可备份恢复；调波次与补给不必重写主流程，不先开发大型编辑器 |
| 测试矩阵与性能 | M2 起记录机器、输入设备和显示条件，M4 完整单人，M5 合作，M6 发布包 | 帧时间／内存／加载目标在测试机确定后设定；覆盖拔插、失焦／休眠恢复、显示回切、长时间运行、存档升级及约 12 种语言 |
| 工作量与资源 | 每次小交付开始时列素材、文案量、依赖、制作／审校负责人和成本范围 | 音乐、翻译、设备等缺口明确；采用自制或委托先确认，不默认承诺预算、购买服务或大量资产同时开工 |

发售候选包不得带有已知的启动失败、可复现崩溃、丢档、主流程无法继续或重复结算问题；其他已知问题按影响记录处理决定。自动回归、目标机器实测与玩家体验认可分别记录，不互相替代。源素材备份和恢复操作另行确认目标位置，不自动上传本地研究资产。

## 控制范围与维护规则

以下作为路线图的执行建议：

- 每轮只推进一个主要可验收目标；新想法先进入对应专题的候选区，除非是当前阻断问题，不中途挤入正在做的版本。
- 每项标明“候选、已确认待做、进行中、待试玩、已验收、阻塞”之一。实现完成与用户认可分开；有代码但未试玩不标为已验收。
- 每轮结束记录本轮交付、验证、剩余问题和下一候选，不让历史进度记录成为第二份排期。
- 涉及游戏的交付包含可直接试玩的应用、操作说明和相应回归；只更新路线图则只做文档检查，不重新打包。
- 追尾汇聚、敌机真实离场、海空滚屏、转场冻结、逻辑坐标和默认关闭的辅助提示继续遵守[开发约定](../AGENTS.md)，不因美术或多人扩展悄悄改变。
- 先用 M1 测出关段、关键机制和单个敌机从设计到验收的实际成本，再估计 M2；正式内容范围在 M3 确认后再估计战役工期。暂不填写发布日期或看似精确的完成率。

下一轮游戏实现候选仍是 M1 的单个环境片段；路线图已纳入关卡内学习、简单故事与逐关流程、音乐反馈、约 12 种语言和发行计划，尚未因此启动新系统或对外执行。M2 及之后保留阶段目标，不拆成大量未经确认的开发任务；每次启动前再确认范围、依赖和退出条件。
