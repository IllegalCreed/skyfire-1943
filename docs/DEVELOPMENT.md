## 候选开发顺序

这是便于安排工作的建议，不是已获批准的排期。本次仓库整理不开始这些新玩法。

1. 统一战役状态，先明确主炮等级、弹种与库存的归属、转场和重试行为，建立跨视角测试。
2. 做有限的 P、E 与两种弹种实验，验证成长价值、追尾有效窗口和攻击路线。
3. 用约 90 秒第一关样段验证脚本波次、补给、转场和一个简化 Boss，不把该样段时长当作最终第一关。
4. 分别试验短厚云接敌和一组高度分层攻击，确认天气与贴海增加的是判断乐趣。
5. 在验证过的状态与碰撞规则上加入保险和检查点，再扩展六关与跨视角航母。

天气或共享装备哪个先做，可另行选择；不因文档顺序自动实施。

## 待确认事项

- 是否正式采用六关及其任务顺序；剧情、Boss 代号和约 27 分钟目标是否保留。
- 三级主炮倍率与两种弹种的具体伤害、范围、射频；僚机在追尾中的相称作用。
- 进攻与防御特殊能力按键、C 库存是否共享，以及能量备用消耗方式。
- 护盾保护哪些碰撞，救援何时触发、是否降级，以及是否允许关闭辅助。
- 检查点保底、快照恢复、继续次数、存盘续玩和最终计分。
- 功能云的高度与距离表达、遮挡时长、敌人丢失视线条件、雨雾和闪电强度。
- 贴海安全带和危险带、攻击高度范围、预警时间，以及奖励计分方式。

## 现有测试入口

从仓库根目录运行：

```sh
bash scripts/test.sh
ruby scripts/check-docs.rb
bash scripts/build-macos.sh
```

测试脚本检查 `SCRIPT ERROR`、`ERROR:`、`Assertion failed` 并要求最终 `SMOKE PASS`，构建先运行测试，不能只看退出码。导出后的应用还需独立测试、签名校验和压缩包完整性检查。

| 回归范围 | 对应检查 |
| --- | --- |
| 三视角战斗、补给、失败、重开、键盘与共享状态 | [主程序 smoke](../src/main.gd) |
| 准心、双弹、阶段、得分与刷新率一致性 | [射击检查](../tests/chase_combat_checks.gd) |
| 密度、上方接近、自主路线与空域滚屏 | [接敌检查](../tests/chase_encounter_checks.gd) |
| 同向追踪、可见老目标、轮廓越界与接缝 | [离场检查](../tests/chase_exit_checks.gd) |
| 露海阈值、连续映射与隐藏水面目标 | [海面检查](../tests/chase_horizon_checks.gd) |
| 海空同量观察横移、机身倾斜无拖景、视差与鱼雷 | [横向滚屏检查](../tests/chase_scroll_checks.gd) |
| 高空云层升降、覆盖、松手与真实上限 | [天空检查](../tests/chase_sky_checks.gd) |

截图参数包括 `--capture-aim`、`--capture-encounter`、`--capture-pursuit`、`--capture-art`、`--capture-altitude`、`--capture-scroll` 和 `--capture-sky`。说明见[项目首页](../README.md)。原型截图检查不能替代真实持续操作和新机制的专用验收。

## 新功能的完成标准

功能需有清楚的规则、实际代码、相关回归测试、实际画面或操作验证，以及更新后的实现状态。主观手感仍需试玩，不能自动从 PASS 推断满意。

只改设计文档时不重打游戏包，不替换已有试玩版本；核对本地链接、Markdown 结构、时间和波次合计即可。文档不附带 ROM、反汇编、第三方游戏美术或音乐，也不默认发布到外部服务。
