## 如何看状态

- **已实现**：当前本地原型中有对应代码。是否已测试、是否获得试玩认可，另行说明；不等于正式版完成。
- **设计方向**：对话中正在沿用的目标或约束，不等于所有细节已拍板，更不等于已经实现。
- **讨论草案**：提出过的具体方案，尚待选择或确认。
- **待验证**：数值、手感或可读性需要实际实验才能定下来。
- **已调整**：旧提案在设计层被替换；除非注明，不代表旧实现也已改掉。

各文档把当前实现与目标方案分开。道具数值、关卡波次、Boss 时长等草案数字不是代码配置，不能直接当作正式平衡参数。

## 当前项目概况

游戏围绕同一架飞机在横版、俯视、追尾三种空间中作战。长期目标是连贯战役，不是三款独立小游戏的拼接。当前 v0.15 的开始游戏进入单人破晓突袭样段：追尾 → 俯视 → 海鸥验证版，含编排波次、补给及胜败结算；原循环玩法另列练习场。保留五类设置、单人改键 / 手柄、单位造型与图鉴，显示辅助默认关闭。基础飞行和汇聚命中沿用 v0.9。没有正式六关、完整部件 Boss、岸防静态炮台、战役存档或检查点。

按最新试玩反馈，当前任务不保护船队；两次视角切换加入连续镜头，海鸥一次接近后保持深度 68、自主摆动，不再装甲回合等待或重复出现。新样段时长取决于真实击破，不强凑原约 90 秒目标。

最近对话形成的设计方向包括共享装备成长、散弹／激光／导弹三路线、沙罗曼蛇式僚机、分数与排行榜，以及低空战术和天气。用户要求保留基础燃油补给，并把关卡、环境的画面与机制、奖励保险提前设计。具体玩法仍按各专题文档标注为草案或待验证；保存进文档不构成开发启动或实现完成。

用户明确不做独立新手教程，在正常关卡中学习；沿用简单岛链突袭故事串联关卡，每关结算后进入下一关，最后展示战役总评与排行榜。音乐音效、战斗反馈、保存兼容、可读性、制作流程与测试验收纳入路线图，当前样段结果页尚不能替代完整战役流程。

2026-10-02 用户进一步确认同时支持本地多人和互联网联机：本地使用键盘 / 手柄组合或同键盘双区域，追尾分屏；互联网各自完整画面。当前仍按本轮 2P 讨论承接，尚未实现。具体公网入口与合作规则见[多人方案](MULTIPLAYER.md)。

开发优先级随后明确为单人体验先完整、多人最后加入，用户已批准本轮单人样段。成长扩展与正式关卡仍分阶段确认，不开发 2P。单双人配置建议分别调校，具体双人参数仍待验证。当前阶段、依赖和下一候选统一见[开发路线图](ROADMAP.md)，具体实施仍需确认。

用户还明确要求支持 Mac 和 Windows，并计划后期在 Steam 发布；2026-10-15 进一步要求把多语言和宣发加入路线图，语言目标约 12 种，明确包含日语、西语、葡语、意大利语、法语、俄语。完整建议清单与地区版本见[发行宣发计划](RELEASE.md)。语言基础随 UI 提前处理，商店和宣传从可展示 Demo 阶段准备，合作仍后置。补充语言、地区版本、渠道、预算与日期待确认；当前 Windows、完整多语言、多人和 Steam 功能尚未实现。

## 维护方式

1. 讨论新机制时，先补入对应专题，并标明状态、影响的视角和待确认问题。
2. 调整旧方案时，直接更新专题中的当前方案；在[决策记录](DECISIONS.md)保留原因，避免互相冲突的版本同时成为规则。
3. 获准实现后，按专题的验收条件开发；涉及其他系统时同步更新交叉引用。
4. 实现完成后，再更新[开发进度](DEVELOPMENT.md)，记录对应代码、测试结果和仍未验证的部分；在[路线图](ROADMAP.md)更新阶段状态，不把代码完成直接标为用户验收通过。
5. 试玩反馈注明版本、视角、操作、预期与实际表现；不能只记录“手感不对”。

不要求每次对话都新建文件。先维护已有专题，内容确实独立且变长时再拆分。文档和代码保存在同一仓库，按用户授权进行提交与同步；本次迁移明确包含 GitHub 同步。迁移目录、备份和工具边界见[仓库说明](REPOSITORY.md)。

## 机制记录模板

新增机制按下列内容说明即可，不必填写无关字段：

- 目的与状态：解决什么问题，是方向、草案还是已实现。
- 玩家操作与反馈：怎么触发，看到什么，结果是什么。
- 共享与差异：跨关卡保存什么，三个视角哪些规则一致、哪些表现不同。
- 边界与依赖：不影响哪些既有规则，需要哪些系统先完成。
- 参数与验收：数值单位、代码来源或草案依据，以及如何证明功能有效。
- 待确认问题：哪些选择仍需项目发起人决定。
